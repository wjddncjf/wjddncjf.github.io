Swift Playgrounds: 코드를 움직임으로 이해하기

학습 중

주제: 변수 · 조건문 · 반복문 · 함수

Swift Playgrounds에서 캐릭터를 움직이는 문제를 풀면서 코드를 한 줄씩 실행해 보고, 반복되는 동작을 함수로 표현하는 방법을 배웠습니다.

고민했던 부분

캐릭터를 움직이는 순서가 길어질수록 moveForward()나 방향 전환 코드를 여러 번 적게 되었습니다. 단순히 코드를 짧게 쓰는 것이 아니라, 반복되는 동작을 어떻게 찾아 하나의 작업으로 묶을지가 궁금했습니다. 특히 앞으로 이동하는 횟수와 방향을 바꾸는 과정을 구분하고, 뒤돌아가는 동작까지 함수로 표현할 수 있는지 고민했습니다.

내가 직접 한 일

계단과 스위치 문제에서 이동 동작을 for 반복문으로 묶고, 반복되는 구간을 solveStairs() 함수로 작성했습니다. 오른쪽으로 두 번 회전하는 코드를 별도 함수로 만들고, 이를 turnAround()처럼 동작이 드러나는 이름으로 표현할 방법을 질문했습니다. 보석 수집·스위치 작동 문제에서도 반복되는 명령들을 찾아 함수와 반복문으로 묶는 방법을 검토했습니다.

AI의 도움과 내가 판단한 부분

AI에게 기존 코드와 같은 동작을 하는 더 간단한 작성법을 물었고, 함수로 나누는 방향을 설명받았습니다. 다만 학습한 for와 func 범위 안에서 이해할 수 있는 방식을 우선으로 두었습니다. 제안된 코드를 그대로 성과로 적기보다, 내가 작성한 부분과 질문을 통해 알아본 부분을 나누어 기록합니다.

다음에 확인할 것

같은 스테이지에서 함수를 사용하기 전과 후의 코드를 직접 실행해 동작이 동일한지 비교하고 싶습니다. 함수 이름만 바꾸는 것과 실제로 반복을 줄이는 것의 차이도 확인할 계획입니다.

배운 내용

변수, 점 표기법, if 조건문, for 반복문, func 함수의 기본 사용법을 학습했습니다.

파이썬 기초: 조건을 코드로 표현하기

학습 중

주제: 조건문 · 반복문 · 변수 누적

조건에 맞는 학생 수를 세는 연습 문제를 단계별로 풀며, 문법을 실제 문제에 연결하는 연습을 했습니다.

고민했던 부분

점수가 60점 이상이면서 90점 이하인 학생 수를 구할 때, 범위 조건 자체는 작성할 수 있어도 조건을 검사한 다음 어떤 값을 언제 증가시켜야 하는지를 단계별로 연결하는 연습이 필요했습니다. 정답 코드를 한 번에 보는 대신, 각 줄이 왜 필요한지 확인하며 문제를 풀고 싶었습니다.

내가 직접 한 일

먼저 if score >= 60 and score <= 90:라는 조건식을 작성해 두 조건을 and로 연결했습니다. 다음 단계에서는 조건을 만족한 학생 수를 세기 위해 count = count + 1을 작성했고, 마지막 출력 단계에 print(count)를 적었습니다. 각 단계마다 내가 작성한 한 줄이 맞는지 확인을 요청하고, 정답을 미리 보지 않은 상태에서 다음 단계로 넘어갔습니다.

AI의 도움과 내가 판단한 부분

AI는 내가 작성한 조건식, 개수 누적식, 출력문을 각각 확인하고 맞는 이유를 설명했습니다. 나는 전체 완성 코드를 먼저 보여 주지 말고 한 단계씩 확인해 달라고 요청해 학습 방식을 정했습니다. 이 기록은 단계별 코드 작성과 피드백을 받은 과정이며, 독립적으로 모든 문제를 해결했다는 뜻은 아닙니다.

다음에 확인할 것

for, if, and, count, total을 함께 사용하는 응용 문제를 힌트 없이 풀어보고, 조건을 통과한 항목의 개수와 값의 합계를 구분할 수 있는지 확인하려 합니다.

배운 내용

조건문과 반복문의 연결, and로 두 조건 표현하기, count 변수 누적, print() 출력의 기본 흐름을 연습했습니다.

#Python#if#for#count

CPU 아키텍처와 OS: 서버를 직접 살펴보기

학습 중

주제: ARM64 · x86_64 · Linux 명령어

서버의 CPU 아키텍처와 운영체제를 확인하고, 명령어 출력 결과를 비교하며 문서로 정리하고 있습니다.

고민했던 부분

명령어를 실행해 출력값을 얻는 것과, 그 값이 실제로 의미하는 바를 설명하는 것은 달랐습니다. 특히 aarch64와 x86_64의 차이, CPU 코어와 논리 CPU의 관계, 운영체제 배포판과 커널의 관계가 헷갈렸습니다. 또한 file이나 readelf의 결과에서 실행 파일의 아키텍처를 어떻게 판단해야 하는지 궁금했습니다.

내가 직접 한 일

서버에 접속해 uname -m, lscpu, nproc 등으로 CPU 정보와 실행 환경을 살펴보았습니다. file /bin/ls, readelf -h /bin/ls 등을 통해 실행 파일 형식을 확인하고 출력 결과를 문서에 정리했습니다. ARM64 기반 Ubuntu 서버를 먼저 살펴본 뒤, x86_64 기반 Ubuntu 및 Rocky Linux 환경을 비교하면서 아키텍처 차이와 배포판 차이를 따로 설명하는 방식으로 정리했습니다.

AI의 도움과 내가 판단한 부분

CPU 아키텍처, SMT와 소프트웨어 스레드, 커널 선점, 가상 주소 등 이해되지 않는 개념을 질문하고 설명을 참고했습니다. 처음 살펴보는 서버는 명령어별 결과를 자세히 기록하되, 비교 대상 서버에서는 공통 설명을 반복하기보다 차이점에 집중하도록 문서 구성 방향을 정했습니다. 실제 출력과 개념 해석을 구분하려고 했습니다.

다음에 확인할 것

같은 x86_64 아키텍처라도 Ubuntu와 Rocky Linux에서 패키지 관리와 기본 설정이 어떻게 달라지는지 더 분명하게 비교하고, 실행 파일의 아키텍처 정보가 설치·실행 가능성과 어떻게 연결되는지 설명해 보려 합니다.

배운 내용

ARM64(AArch64)와 x86_64, Linux 배포판과 커널, CPU 정보 조회, ELF 실행 파일 확인 등의 기초를 학습했습니다.
